# 테스트 실행 순서와 상태 격리 기준

API 자동화 테스트는 파일명, 수집 순서, 이전 테스트의 성공 여부와
관계없이 **단독 실행과 전체 실행에서 같은 결과를 내는 것**을 목표로
합니다.

## 1. 적용된 격리 정책

-   API 요청 횟수와 5xx 중단 상태는 각 테스트 시작 전과 종료 후
    초기화합니다.
-   5xx 중단 상태는 해당 테스트 안에서 후속 API 호출을 차단하는 데
    사용합니다.
-   변경될 수 있는 서버 응답을 session fixture의 공유 상태로 저장하지
    않습니다.
-   테스트가 만든 외부 데이터가 다른 테스트의 사전조건이라고 가정하지
    않습니다.
-   생성·수정 데이터는 Cleanup Registry 또는 fixture teardown에서
    삭제·원복합니다.
-   역할별 인증처럼 명시적으로 공유할 수 있는 설정·인증 정보와 테스트별
    변경 상태를 구분합니다.

## 2. Cleanup Registry

공통 정리 도구는 `test_support.cleanup`의 Cleanup Registry를 사용합니다.

상태 변경 테스트는 데이터 생성 또는 변경 직후 정리 callback을 등록하고,
teardown에서 **등록 역순(LIFO)** 으로 실행합니다. 하나의 정리 작업이
실패하더라도 가능한 나머지 정리를 계속 수행한 뒤 정리 실패를 보고합니다.

이 구조의 목적은 다음과 같습니다.

-   중간 assertion 실패로 일반 복원 코드가 실행되지 않는 상황 방지
-   후속 TC에 이전 테스트 데이터가 남는 문제 최소화
-   생성 순서의 반대로 정리해 데이터 의존성 충돌 감소
-   다른 테스트가 만든 데이터까지 광범위하게 삭제하지 않고 해당 테스트가
    변경한 대상만 정리

게시판 생성 테스트처럼 삭제 경로가 필요한 기능은
`LXP_BOARD_ARTICLE_DELETE_PATH`가 설정된 경우에만 실행하도록 구성합니다.
삭제 API가 확정되지 않은 환경에서는 생성 테스트를 Skip하여 자동화가
정리할 수 없는 데이터를 남기지 않도록 합니다.

## 3. 상태 변경 테스트

POST/PATCH/DELETE처럼 서버 상태를 변경할 수 있는 요청은 일반 조회 요청과
분리하여 보호합니다.

`LXP_ALLOW_MUTATING_REQUESTS=true`가 설정되지 않은 상태에서는 상태 변경
요청을 허용하지 않습니다. 테스트 코드에서도 명시적인 확인 조건을 함께
사용해 잘못된 실행으로 QA 데이터가 변경되는 것을 방지합니다.

일부 응시 기록 초기화처럼 영향 범위가 더 큰 동작은
`LXP_ALLOW_IRREVERSIBLE_TEST_RESET`을 별도 조건으로 사용합니다. 일반
회귀 실행에서 해당 플래그를 임의로 활성화하지 않습니다.

## 4. 순서 의존성 확인

현재 pytest 설정 자체는 테스트 순서를 무작위화하지 않습니다. 따라서 순서
의존성을 점검할 때는 동일 테스트를 다음 범위에서 비교합니다.

``` powershell
python -m pytest <단일 테스트 nodeid> -q
python -m pytest <기능 디렉터리> -q
python -m pytest api/tests -q
```

세 범위에서 결과가 달라진다면 다음 항목을 우선 확인합니다.

-   이전 TC가 생성·수정한 데이터에 의존하는지
-   fixture scope가 불필요하게 넓은지
-   모듈 전역에 응답·ID·사용자 상태를 저장하는지
-   원본 값 복원이 실패하거나 누락되는지
-   테스트 전 사전조건을 다시 조회하지 않고 이전 실행 값을 재사용하는지

`PYTEST_RANDOM_ORDER_SEED`는 현재 테스트 순서를 변경하는 기능으로
연결되어 있지 않은 예약 환경변수입니다.

## 5. 테스트 작성 규칙

1.  다른 TC가 데이터를 생성하거나 수정했다고 가정하지 않습니다.
2.  조회 기준 데이터는 테스트 또는 function fixture 시작 시 필요한
    상태를 다시 확인합니다.
3.  모듈 전역 변수에 응답 객체, 생성 ID, 변경 가능한 사용자 상태를
    저장하지 않습니다.
4.  session fixture에는 URL·설정·역할별 인증처럼 명시적으로 공유 가능한
    값만 둡니다.
5.  생성·수정 테스트는 대상 ID와 원본 값을 확보하고 Cleanup Registry
    또는 fixture teardown에서 복구합니다.
6.  정리 경로가 없는 상태 변경 테스트는 자동 실행하지 않습니다.
7.  단독 실행, 기능 디렉터리 실행, 전체 실행에서 같은 판정이 나오는
    구조를 유지합니다.

## 6. 실행 환경 종료 후 검증 범위

원 프로젝트의 Dev 환경이 종료된 이후에는 실제 API 회귀 실행으로 격리성을
재검증할 수 없습니다. 저장소 구조 변경 시에는 최소한 다음 정적 검증을
수행할 수 있습니다.

``` powershell
python -m compileall -q api performance scripts test_support
python -c "import api; import performance; import test_support; print('IMPORT OK')"
python -m pytest --collect-only -q
```

이 검증은 Python 문법, 패키지 import, pytest 수집 구조를 확인하는
용도이며 실제 서버 응답이나 상태 원복 성공까지 보장하지는 않습니다.
