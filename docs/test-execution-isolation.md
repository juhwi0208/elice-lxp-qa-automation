# 테스트 실행 순서와 상태 격리 기준

테스트는 파일명, 수집 순서, 이전 테스트의 성공 여부와 관계없이 단독 실행과
전체 실행에서 같은 결과를 내야 한다.

## 적용된 격리 정책

- API 요청 횟수와 5xx 중단 상태는 테스트 시작 전과 종료 후 초기화한다.
- 5xx 중단 상태는 해당 테스트 안에서만 유지된다. 실제 `AbortTestError`가
  pytest 밖으로 전파되면 기존 정책대로 실행을 즉시 중단한다.
- 변경될 수 있는 서버 응답을 session fixture에 저장하지 않는다.
- 일반 `driver` fixture는 E2E 테스트마다 새로 만들고 종료한다. 로그인 비용이 큰
  역할별 인증 driver와 AppShell은 session scope로 재사용하므로 각 테스트가
  시작 화면으로 직접 이동하고 이전 화면 상태에 의존하지 않게 한다.
- 테스트가 만든 외부 데이터는 다른 테스트가 사용한다고 가정하지 않는다.
- 생성 데이터의 실제 삭제는 cleanup fixture에서 담당한다.

## 생성 데이터 cleanup fixture

`cleanup_registry`에 생성 직후 ID와 삭제 callback을 등록한다. teardown은
등록 역순으로 실행되며 하나가 실패해도 나머지 정리를 계속한다.

게시판 생성 테스트는 `LXP_BOARD_ARTICLE_DELETE_PATH`가 설정된 경우에만
실행한다. 삭제 API가 확정되지 않은 환경에서는 테스트를 건너뛰어 데이터가
남는 것을 방지한다. 경로에는 기관 자리표시자 `{org}`를 사용할 수 있다.

## 순서 의존성 확인

현재 pytest 설정은 수집 순서를 임의로 섞는 플러그인을 사용하지 않는다. 순서
의존성을 확인할 때는 먼저 대상 테스트를 단독 실행하고, 이어서 기능 디렉터리와
전체 Suite에서 실행해 결과가 같은지 비교한다. `PYTEST_RANDOM_ORDER_SEED`는 향후
순서 무작위화 도구를 연결할 때 사용할 예약 변수이며 현재 실행 순서를 바꾸지 않는다.

```powershell
python -m pytest <단일 테스트 nodeid> -q
python -m pytest <기능 디렉터리> -q
python -m pytest part1_api_automation/tests -q
```

cleanup이 보장되지 않은 변이 테스트는 순서 검증에 포함하지 않는다.

## 테스트 작성 규칙

1. 다른 TC가 데이터를 생성하거나 수정했다고 가정하지 않는다.
2. 조회 기준 데이터는 테스트 또는 function fixture 시작 시 다시 조회한다.
3. 모듈 전역 변수에 응답, 생성 ID, 사용자 상태를 저장하지 않는다.
4. session fixture에는 URL·설정·API 객체와 역할별 인증 세션처럼 명시적으로
   공유하기로 한 값만 두고, 테스트별 화면·서버 상태는 저장하지 않는다.
5. 생성·수정 테스트는 원본 값을 저장하고 `yield` fixture의 teardown에서 복구한다.
6. 테스트 단독 실행, 기능 디렉터리 실행, 전체 실행에서 결과가 같은지 확인한다.
